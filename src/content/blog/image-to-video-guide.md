AI 영상을 실무에 쓰는 사람들은 대부분 텍스트가 아니라 **이미지에서 시작**합니다. 텍스트만으로 영상을 만들면 인물 얼굴, 옷, 배경이 매번 바뀌지만, 이미지를 넣으면 원하는 장면을 그대로 움직일 수 있기 때문입니다. 이 글에서는 이미지 한 장으로 쓸 만한 영상을 뽑는 과정을 순서대로 정리했습니다.

## 텍스트 vs 이미지, 뭐가 다를까

| 비교 | 텍스트로 영상 | 이미지로 영상 |
|---|---|---|
| 인물·배경 일관성 | 매번 달라짐 | 이미지 그대로 유지 |
| 결과 예측 | 어려움 | 쉬움 |
| 준비물 | 프롬프트만 | 원본 이미지 + 움직임 프롬프트 |
| 크레딧 낭비 | 많음 (여러 번 다시 뽑기) | 적음 |
| 추천 용도 | 아이디어 스케치, 배경 | 광고, 홍보, 시리즈 콘텐츠 |

## 1단계: 원본 이미지 준비

영상 품질의 절반은 원본 이미지에서 결정됩니다.

| 좋은 이미지 | 피해야 할 이미지 |
|---|---|
| 해상도가 높고 선명함 | 작거나 흐린 이미지 |
| 인물 얼굴·손이 또렷함 | 얼굴이 작거나 가려짐 |
| 움직일 공간이 있는 구도 | 화면 끝에 꽉 찬 구도 |
| 만들 영상과 같은 비율 (9:16, 16:9) | 비율이 달라 잘리는 이미지 |
| 글자가 없거나 적음 | 글자·로고가 많음 (뭉개짐) |

**비율은 이미지 단계에서 맞추세요.** 릴스·쇼츠용이면 처음부터 9:16 이미지를 만들어야 합니다. 영상 도구에서 비율을 바꾸면 위아래가 잘리거나 AI가 빈 곳을 채우면서 어색해집니다.

원본 이미지는 나노바나나 같은 이미지 생성 도구나 클링 안의 이미지 생성 기능으로 만들 수 있습니다. 어떤 도구를 쓰든 영상으로 넘기기 전에 얼굴, 손, 비율 세 가지를 확대해서 확인하면 재생성 횟수가 크게 줄어듭니다.

## 2단계: 움직임 프롬프트 쓰기

이미지 영상의 프롬프트는 **"무엇이 어떻게 움직이는지"만** 씁니다. 이미지에 이미 보이는 인물, 옷, 배경을 다시 설명하면 AI가 그걸 새로 그리려다 원본과 달라질 수 있습니다.

| 나쁜 예 | 좋은 예 |
|---|---|
| 흰 셔츠를 입은 30대 여성이 햇살 드는 거실 소파에 앉아 있다 | 여성이 천천히 고개를 들어 카메라를 보며 미소 짓는다 |
| 아름답고 멋진 아파트 | 카메라가 천천히 앞으로 날아가며 단지 전체를 보여준다 |
| 맛있어 보이는 커피 | 커피잔에서 김이 천천히 피어오른다, 정지된 카메라 |

움직임은 세 종류로 나눠 생각하면 쉽습니다.

| 종류 | 예시 프롬프트 |
|---|---|
| 피사체 움직임 | 고개를 돌린다, 걸어간다, 머리카락이 바람에 날린다 |
| 카메라 움직임 | slow dolly in, slow pan right, aerial drone shot |
| 환경 움직임 | 나뭇잎이 흔들린다, 김이 오른다, 구름이 흘러간다 |

5초 영상이면 **피사체 동작 1개 + 카메라 무빙 1개** 정도가 가장 안정적입니다. 카메라 용어는 [AI 영상 프롬프트 카메라·조명 용어 총정리](../ai-video-prompt-camera-lighting/) 글에 표로 정리해 두었습니다.

## 3단계: 설정 고르기

| 설정 | 추천 | 이유 |
|---|---|---|
| 길이 | 테스트는 5초, 확정 후 10초 | 크레딧 절약 |
| 모델 | 테스트는 저가 모델, 최종은 최신 모델 | 구도 확인엔 저가 모델로 충분 |
| 화질 | 최종본만 고화질 | 고화질은 크레딧이 많이 듦 |
| 개수 | 한 번에 1개씩 | 결과 보고 프롬프트 수정 |

## 4단계: 시작·끝 프레임으로 장면 전환

클링, Seedance 같은 도구는 **첫 장면 이미지와 마지막 장면 이미지**를 같이 넣을 수 있습니다. AI가 두 이미지 사이를 자연스럽게 이어 주기 때문에 이런 영상에 좋습니다.

| 활용 | 시작 이미지 | 끝 이미지 |
|---|---|---|
| 변신 | 평상복 인물 | 정장 입은 같은 인물 |
| 시간 변화 | 낮 풍경 | 같은 장소의 밤 풍경 |
| 공간 이동 | 현관 | 같은 집 거실 |
| 제품 공개 | 닫힌 상자 | 열린 상자 속 제품 |

두 이미지의 **인물·구도가 비슷할수록** 결과가 자연스럽습니다. 완전히 다른 두 장면을 넣으면 중간이 뭉개지기 쉽습니다.

## 자주 생기는 문제와 해결법

| 문제 | 원인 | 해결 |
|---|---|---|
| 얼굴이 바뀜 | 얼굴이 작거나, 고개를 크게 돌림 | 얼굴이 큰 이미지 사용, 동작을 작게 |
| 손가락이 이상함 | 손이 화면에서 크게 움직임 | 손 동작 빼기, 손이 덜 보이는 구도 |
| 거의 안 움직임 | 프롬프트가 약하거나 없음 | 동작을 구체적으로, 카메라 무빙 추가 |
| 너무 과하게 움직임 | 동작을 여러 개 씀 | 동작 1개로 줄이기 |
| 글자가 뭉개짐 | AI가 글자를 다시 그림 | 글자는 편집 단계에서 자막으로 넣기 |
| 배경이 출렁임 | 카메라 무빙이 큼 | static shot 또는 느린 무빙 |

## 마무리

이미지 → 영상 방식은 "이미지에서 다 정하고, 영상은 움직임만 더한다"가 핵심입니다. 원본 이미지를 꼼꼼히 만들수록 영상 재생성 횟수가 줄고, 결과적으로 크레딧과 시간이 모두 절약됩니다.
