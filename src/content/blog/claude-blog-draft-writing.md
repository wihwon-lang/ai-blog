블로그를 꾸준히 운영하려면 글 한 편에 들어가는 시간을 줄여야 합니다. Claude 같은 AI 챗봇을 쓰면 개요와 초안을 빠르게 만들 수 있지만, 그대로 올리면 정보가 틀리거나 다른 글과 비슷한 문장이 되기 쉽습니다. 이 글은 블로그를 운영하는 분들께 Claude로 초안을 쓰는 순서와 프롬프트, 그리고 발행 전에 꼭 거쳐야 할 검수 요령을 정리한 글입니다.

## Claude 요금제와 블로그 작업에 쓸 기능

블로그 초안 작업은 무료 요금제로도 시작할 수 있습니다. 다만 글을 자주 쓰거나 자료를 많이 올린다면 사용량이 넉넉한 유료 요금제가 편합니다. 아래 표는 2026년 10월 Claude 공식 요금 페이지 기준입니다.

| 요금제 | 가격 (미국 달러) | 블로그 작업 관점의 특징 |
|---|---|---|
| Free | 무료 | 웹 검색, 파일 만들기, 대화 간 메모리, 프로젝트 최대 5개, Sonnet·Haiku 모델 |
| Pro | 월 20달러 (연간 결제 시 월 17달러) | 사용량 증가, 프로젝트 무제한, 리서치 기능, Opus 등 더 많은 모델 |
| Max | 월 100달러부터 | Pro 대비 5배 또는 20배 사용량, 더 긴 출력 |

요금과 포함 기능은 자주 바뀌므로 결제 전에 공식 요금 페이지에서 다시 확인하는 것을 추천합니다.

블로그 작업에서 특히 유용한 기능은 세 가지입니다.

| 기능 | 하는 일 | 블로그에 쓰는 법 |
|---|---|---|
| 프로젝트(Projects) | 지침과 참고 파일을 묶어 두고, 그 안의 모든 대화가 같은 지침을 따르게 함 | 블로그 작성 규칙, 카테고리 설명, 기존 글 목록을 넣어 두기 |
| 스타일(Styles) | 글쓰기 예시를 올리면 문장 길이·말투·구조를 분석해 맞춤 스타일을 만듦 | 내가 쓴 글 2~3편을 올려 말투를 맞추기 |
| 웹 검색 | 최신 정보를 찾아 답변에 반영 | 요금, 버전, 제도 같은 최신 정보의 출처 찾기 |

프로젝트를 한 번 만들어 두면 새 글을 쓸 때마다 규칙을 다시 설명하지 않아도 됩니다. 블로그 운영에서 가장 시간을 아껴 주는 기능입니다.

## 블로그용 프로젝트 세팅하기

프로젝트 지침에는 "이 블로그가 누구를 위한 블로그인지"와 "글을 어떻게 써야 하는지"를 적습니다. 지침이 구체적일수록 초안을 덜 고치게 됩니다.

```
너는 'AI 작업실' 블로그의 글 작성 도우미야.
독자: 생성형 AI를 업무와 부업에 쓰고 싶은 초보자
문체: 존댓말(~합니다), 쉬운 말, 문장은 짧게
구성: 도입 2~3문장 → 소제목 4~7개 → 마무리
규칙:
- 비교, 단계, 요금, 문제 해결은 표로 정리
- 확인되지 않은 숫자는 쓰지 말고 [확인 필요]로 표시
- "무조건", "100%" 같은 과장 표현 금지
- 내가 겪지 않은 경험담을 지어내지 말 것
```

참고 파일로 올리면 좋은 자료도 정리해 둡니다.

| 파일 | 넣는 이유 |
|---|---|
| 블로그 작성 규칙 문서 | 분량, 구성, 금지 표현을 매번 지키게 함 |
| 기존 글 제목·주소 목록 | 중복 주제를 피하고 내부 링크 후보를 찾게 함 |
| 잘 쓴 기존 글 1~2편 | 표 사용 방식과 말투의 기준으로 삼게 함 |
| 자주 다루는 도구의 공식 문서 요약 | 기본 사실을 틀리지 않게 함 |

"확인되지 않은 숫자는 [확인 필요]로 표시"라는 규칙이 특히 중요합니다. AI는 그럴듯한 숫자를 만들어 낼 수 있기 때문에, 확인할 부분을 표시하게 해 두면 검수할 때 놓치지 않습니다.

## 1단계: 주제와 개요 만들기

초안을 바로 쓰게 하기보다 개요를 먼저 받는 편이 결과가 좋습니다. 개요 단계에서 방향을 고치면 본문을 통째로 다시 쓰는 일이 줄어듭니다.

```
주제: [주제]
검색할 사람: [누가, 어떤 상황에서 이 글을 찾을지]
요청:
1. 검색어가 앞쪽에 오는 제목 후보 5개
2. 이 사람이 궁금해할 질문 10개
3. 질문을 묶어 소제목 5~6개로 개요 만들기
4. 소제목마다 넣을 표 아이디어 한 줄
```

개요를 받은 뒤에는 다음과 같이 다듬습니다.

| 다듬는 요청 | 효과 |
|---|---|
| "독자가 가장 먼저 궁금해할 순서로 소제목을 다시 배열해 줘" | 읽는 흐름이 자연스러워짐 |
| "기존 글 목록과 겹치는 소제목이 있으면 알려 줘" | 중복 내용 방지, 내부 링크 후보 확보 |
| "소제목 중 최신 정보 확인이 필요한 것을 표시해 줘" | 사실 확인할 부분을 미리 파악 |
| "이 개요에서 빠진 관점이 있으면 2개만 제안해 줘" | 글의 깊이 보강 |

## 2단계: 본문 초안 쓰기

개요가 정해지면 소제목 단위로 나눠 쓰게 하는 방법을 추천합니다. 한 번에 긴 글을 요청하면 뒤로 갈수록 내용이 얕아지는 경우가 많기 때문입니다.

```
위 개요의 2번 소제목만 써 줘.
분량: 600~800자
조건:
- 첫 문장에서 이 소제목의 결론을 먼저 말하기
- 비교나 단계가 있으면 표 1개 포함
- 사실 정보에는 기준 시점을 적고, 확인 못 한 숫자는 [확인 필요]
```

초안 품질을 높이는 요청 방법을 정리하면 다음과 같습니다.

| 상황 | 이렇게 요청하기 |
|---|---|
| 문장이 길고 딱딱할 때 | "한 문장에 하나의 정보만 담고 문장을 짧게 나눠 줘" |
| 내용이 뻔할 때 | "초보자가 실제로 막히는 지점 3가지를 중심으로 다시 써 줘" |
| 표가 부족할 때 | "이 단락에서 표로 바꿀 수 있는 내용을 표로 바꿔 줘" |
| 말투가 블로그와 다를 때 | 스타일 기능에서 내 글로 만든 맞춤 스타일을 선택 |
| 같은 표현이 반복될 때 | "자주 반복되는 표현을 찾아 다른 말로 바꿔 줘" |

숏폼 대본처럼 짧은 글을 쓸 때의 프롬프트 요령은 [ChatGPT로 숏폼 대본·콘티 짜는 법](../chatgpt-shorts-script/)에서 따로 정리했습니다. 같은 템플릿을 Claude에서도 그대로 쓸 수 있습니다.

## 3단계: 사실 확인과 검수

초안을 다 받았다면 가장 중요한 단계가 남았습니다. AI가 쓴 글은 문장이 매끄러워서 틀린 부분이 눈에 잘 띄지 않습니다. 발행 전에는 아래 항목을 하나씩 확인하는 것이 좋습니다.

| 검수 항목 | 확인 방법 |
|---|---|
| 요금, 모델 이름, 버전 | 공식 홈페이지·요금 페이지에서 직접 확인하고 기준 시점 적기 |
| 법·제도, 약관 | 정부·기관 공식 자료나 서비스 약관 원문 확인 |
| [확인 필요] 표시 | 하나도 남지 않았는지 검색으로 확인 |
| 지어낸 경험담 | "써 보니", "테스트해 보니" 같은 문장이 있으면 삭제하거나 사실로 바꾸기 |
| 과장 표현 | "무조건", "최고", "100%" 같은 단어 찾아 바꾸기 |
| 링크 | 내부 링크와 출처 링크가 실제로 열리는지 확인 |
| 중복 | 기존 글과 같은 내용을 반복하지 않는지 확인 |

검수에도 Claude를 쓸 수 있습니다. 초안을 쓴 대화가 아니라 새 대화에서 검수를 요청하면, 앞선 대화의 흐름에 끌려가지 않고 더 냉정하게 확인하는 데 도움이 됩니다.

```
아래 블로그 글을 검수해 줘. 고치지 말고 문제만 표로 정리해.
열: 위치 / 문제 유형 / 내용 / 수정 제안
문제 유형: 사실 확인 필요, 과장 표현, 근거 없는 경험담, 어색한 문장, 중복 내용
[글 붙여 넣기]
```

검수 결과를 받은 뒤 최종 판단은 사람이 합니다. 특히 사실 확인은 AI의 답변이 아니라 공식 출처를 기준으로 해야 합니다.

## 구글 검색과 AI 글에 대해 알아 둘 점

AI로 쓴 글이 검색에서 불리한지 궁금해하는 분이 많습니다. 구글 검색 센터의 안내는 콘텐츠를 어떻게 만들었는지보다 콘텐츠의 품질과 유용성에 초점을 둡니다. 반대로 검색 순위를 조작할 목적으로 사람에게 도움이 되지 않는 페이지를 대량으로 만드는 것은 '대규모 콘텐츠 악용(scaled content abuse)' 스팸 정책에 해당하며, 이 정책은 AI로 만들었든 사람이 만들었든 똑같이 적용됩니다.

| 피해야 할 방식 | 권장하는 방식 |
|---|---|
| 같은 틀에 키워드만 바꾼 글을 대량 발행 | 독자의 질문에 실제로 답하는 글을 꾸준히 발행 |
| AI 초안을 확인 없이 그대로 발행 | 사실 확인과 검수를 거쳐 발행 |
| 다른 사이트 글을 요약·재조합만 한 글 | 비교표, 체크리스트처럼 정리 방식에 고유한 가치를 더함 |
| 출처 없는 숫자와 단정 | 기준 시점과 공식 출처 안내를 함께 표기 |

애드센스 승인이나 검색 노출을 준비하는 블로그라면 발행 속도보다 글 하나하나의 정확도를 우선하는 편이 안전합니다.

## 마무리

Claude로 블로그 글을 쓸 때는 "프로젝트에 규칙 정리 → 개요 먼저 받기 → 소제목 단위로 초안 쓰기 → 새 대화에서 검수 → 공식 출처로 사실 확인" 순서를 지키는 것이 핵심입니다. AI는 초안을 빠르게 만드는 역할을 맡고, 정보의 정확성과 최종 판단은 운영자가 맡는다고 생각하면 됩니다.

AI로 만든 결과물을 상업적으로 쓸 때의 저작권 문제가 궁금하다면 [AI 영상 상업적 이용·저작권 정리](../ai-video-copyright-commercial/)도 함께 참고해 보세요. 영상 이야기가 중심이지만 AI 결과물의 권리를 어떻게 보는지에 대한 기본 원칙은 글에도 비슷하게 적용됩니다.
